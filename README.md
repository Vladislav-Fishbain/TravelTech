## Ключевые требования и паттерны системы (NFR)

### 1. Шифрование данных и комплаенс хранения ПДн (Паспорта)
Все критически важные персональные данные (PII), привязанные к таблице `passport_data`, симметрично шифруются на уровне приложения с использованием алгоритма **AES-256-GCM**. Ключи изолированы во внешней инфраструктуре управления ключами (Key Management Service / HashiCorp Vault). 
Сроки хранения строго ограничены: записи содержат автоматически рассчитываемое поле `expires_at` по формуле `trips.end_date + 24 часа`. Изолированный cron-воркер ежедневно выполняет жесткое удаление (`DELETE`) просроченных записей. Каскадные ограничения (`ON DELETE CASCADE`) гарантируют полную очистку связанных исторических ссылок.

### 2. Конвейер обработки входящих Email-рассылок
Для фиксации сбоев и задержек рейсов через почтовые рассылки авиакомпаний архитектура предусматривает входящий SMTP-шлюз с маршрутизацией на изолированный воркер обработки писем:
1. Каждая уникальная поездка группы получает выделенный виртуальный почтовый адрес (`trip-[id]@://alfredroutes.com`).
2. Входящие многокомпонентные MIME-пакеты писем очищаются от HTML-тегов и проходят сопоставление по регулярным выражениям.
3. Парсер извлекает 6-значный буквенно-цифровой код бронирования (PNR) с помощью регулярного выражения `\b[A-Z0-9]{6}\b`, фиксирует маркеры изменения статуса (`"delayed"`, `"cancelled"`, `"flight change"`) и асинхронно отправляет готовый payload напрямую в шину Apache Kafka.

### 3. Отказоустойчивость интеграций (Паттерн Circuit Breaker)
Исходящие соединения с глобальными дистрибьюторскими системами (Amadeus GDS) и агрегаторами отелей (Booking.com API) строго контролируются конфигурациями прокси-серверов Envoy / Resilience4j. 
Если доля ошибок на внешних шлюзах достигает или превышает `15%` в течение скользящего окна мониторинга в `60 секунд`, предохранитель (`Circuit Breaker`) переходит в состояние `Open` («разомкнут») на `30 секунд`. В этот период платформа мгновенно перехватывает трафик к упавшей внешней системе и отвечает локальными fallback-кэшами или предопределенными заглушками, предотвращая каскадный отказ и нехватку системных ресурсов бэкенда.
